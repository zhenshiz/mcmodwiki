<h1 id="mod-introduction" data-toc-id="mod-introduction">Mod introduction</h1>
<p>This is a dialog similar to Gal, designed for the creators of integration packs or maps. You can use packets to write the topic style and dialogue text for the dialog box, and provide some events for KubeJS to use.</p>
<h2 id="instructions" data-toc-id="instructions">Instructions</h2>
<p>ChatBox adds custom commands, allowing developers to interact with mods using them.</p>
<ul>
  <li>
    <p>
      <code>/chatbox skip &lt;数据包路径: ResourceLocation&gt; &lt;组名: String&gt; &lt;序号: int&gt; &lt;目标实体: Target1 Target2 Target3 ...&gt;</code>
      Jump to the specified conversation</p>
    <ul>
      <li>
        <p><strong>Packet path</strong>: Location of the dialogue text file</p>
      </li>
      <li>
        <p><strong>Group name</strong>: The identifier for a conversation within a dialogue text file</p>
      </li>
      <li>
        <p><strong>Serial number</strong>(Optional, default is 0): The sequence number of a dialogue in a segment</p>
      </li>
      <li>
        <p>
          <strong>Target entity</strong>(Optional): Specify the target entity of the dialogue, separated by spaces, used to reference the attributes of the target entity in dialogue text or commands (<strong>See details for details</strong><a
            href="?file=&quot;10-扩展功能.占位符.md&quot;"><strong>Placeholders</strong></a>) or interact.
        </p>
      </li>
    </ul>
  </li>
  <li>
    <p><code>/chatbox theme &lt;数据包路径: ResourceLocation&gt;</code> Switch the dialog box theme</p>
  </li>
  <li>
    <p><code>/chatbox open</code> Open the most recent conversation</p>
  </li>
  <li>
    <p>
      <code>/chatbox maxTriggerCount &lt;数据包路径: ResourceLocation&gt; &lt;最大访问次数:int&gt;</code>
      Set the maximum number of visits for a conversation</p>
    <ul>
      <li>
        <p><strong>Maximum number of visits</strong>:-1 indicates unlimited access, 0 means inaccess, and non-0 sets the maximum number of accesses</p>
      </li>
    </ul>
  </li>
  <li>
    <p><code>/chatbox maxTriggerCount reset</code> Reset the maximum number of accesses</p>
  </li>
  <li>
    <p><code>/chatbox command nextDialogue</code> Jump to the next sentence</p>
  </li>
  <li>
    <p><code>/chatbox command autoPlay &lt;开关：Boolean&gt;</code> Turn on and off automatic conversation</p>
  </li>
  <li>
    <p><code>/chatbox command isScreen &lt;开关：Boolean&gt;</code>
      true is the screen theme mode, which offers dialogue and is more immersive. You can select options with the mouse; false is the rendering theme mode, where players can interact normally by using the mouse and keys to interact with the dialog box (theme settings can prevent players from freely jumping to the next dialogue; see details).<a
        href="#key-prompts">Key prompts</a>）</p>
  </li>
  <li>
    <p><code>/chatbox mvelTest &lt;表达式：String&gt; &lt;在服务端：Boolean&gt;</code>
      Test the execution of a piece of mvel code. The last parameter is set to true to mean execution on the server side, false means it runs on the client. The return value of the execution code is sent to the player. If an error occurs, the log will show error messages (to avoid polluting the log, other places where mvel functionality is used will not output errors).
    </p>
  </li>
</ul>
<h2 id="packet-path" data-toc-id="packet-path">Packet path</h2>
<p>ChatBox will automatically load the JSON file corresponding to the path in the dialog box.</p>
<p>
  The file path for the dialog box topic is<code>data/&lt;命名空间&gt;/chatbox/theme/&lt;文件名&gt;.json</code>, the file path of the dialog text is <code>data/&lt;命名空间&gt;/chatbox/dialogues/&lt;文件名&gt;.json</code>。
  All these documents can be approved<code>/reload</code>command to reload, and after reloading, it jumps to a new dialogue line that takes effect.</p>

<h3 id="components" data-toc-id="components">Components</h3>
<p>
  What are components? Everything you see in the dialog interface of this mod is a component, including dialog boxes, options, chat history buttons, portraits, etc., all inheriting component attributes, so they share the same basic parameter types (such as position, size, etc.). The basic parameters of components serve exactly the same function. After a unified introduction here, the following content will focus only on parameters unique to different components.
</p>
<p>The basic parameters of the components are as follows:</p>
<ul>
  <li>
    <p><code>x</code>:
      The x-axis of a component, measured as a percentage relative to the window width, 0 is the left side of the window, 100 is the right side of the window. Anything beyond this range will not be displayed in the window (completely).</p>
  </li>
  <li>
    <p><code>y</code>:
      The vertical axis of a component, measured as a percentage relative to the window height, 0 is the top of the window, 100 is the bottom of the window. Anything beyond this range will not be displayed in the window (in full).</p>
  </li>
  <li>
    <p><code>width</code>: The width of the component,<strong>The unit is related to the next parameter</strong>。</p>
  </li>
  <li>
    <p><code>widthReference</code>:
      Width reference, default value is <code>screen_width</code>。 Optional values include:<code>screen_width</code>(Percentage relative to window width),<code>screen_height</code>(Percentage relative to window height),<code>pixel</code>(Absolute pixel values, not recommended).
    </p>
  </li>
  <li>
    <p><code>height</code>: The height of the component,<strong>The unit is related to the next parameter</strong>。</p>
  </li>
  <li>
    <p><code>heightReference</code>:
      Height reference, default value is <code>screen_height</code>。 Optional values are the same<code>widthReference</code>Parameters.</p>
  </li>
  <li>
    <p><code>scale</code>: The component's scaling ratio is set to 1 by default. Render using the component's<strong>Center location</strong>Scale as the reference.
    </p>
  </li>
  <li>
    <p><code>alignX</code>:
      The component's horizontal alignment mode has a default value of <code>left</code>。 The optional value is<code>left，center，right</code>。</p>
  </li>
  <li>
    <p><code>alignY</code>:
      The vertical alignment of components has a default value of <code>top</code>。 The optional value is<code>top，center，bottom</code>。</p>
  </li>
  <li>
    <p><code>renderOrder</code>:
      The rendering order of components: the higher the value, the higher the rendering layer. You can think of it as a layer, where components with a higher value are rendered above the smaller component. Different components have different default rendering order, which will be explained separately later.
    </p>
  </li>
  <li>
    <p><code>brightness</code>:
      The component's brightness has a default value of <code>100</code>, with units expressed as percentages. The range is 0-100; when it's 0, the component looks pitch black.</p>
  </li>
  <li>
    <p><code>opacity</code>:
      The transparency of the component, with the default value is <code>100</code>, with units expressed as percentages. The range is 0-100; at 0, the module is completely transparent; at 100, the module is completely opaque.</p>
  </li>
  <li>
    <p><code>angle</code>:
      The rotation angle of the component, with a default value of <code>0</code>, with units in degrees. Render using the component's<strong>Center location</strong>Rotate clockwise to the reference point.</p>
  </li>
  <li>
    <p><code>hidden</code>: Whether components are hidden, the default value is <code>false</code>。 Used in conjunction with component rendering events, generally not needed.</p>
  </li>
  <li>
    <p><code>renderEvents</code>: Component rendering event,<strong>See details for details</strong><a
        href="?file=&quot;13-扩展功能.组件渲染事件.md&quot;">Component rendering event</a>。</p>
  </li>
</ul>
<div type="info" data-type="admonition" data-admo-type="info">
  <div data-type="admonition-title">INFO</div>
  <div data-type="admonition-content">
    <p>
      If the component has additional rendered text,<code>scale, brightness, opacity, angle</code>These parameters also affect text rendering.
    </p>
  </div>
</div>

<h4 id="rendering-of-biological-entities" data-toc-id="rendering-of-biological-entities">Rendering of biological entities</h4>
<p>Although solid rendering is one type of portrait, many of its parameters differ from the portrait effect, so they will be introduced separately here. The subtype designed to be written in JSON files is easy to write.</p>
<ul>
  <li>

  </li>
  <li>
    <p>

      <code>stareAtX, stareAtY</code>(Optional):<code>stareAt</code>Yes<code>point</code>Valid at the time, with units expressed as percentages.
    </p>
  </li>

  </li>

<p>Q：<code>renderOrder</code>What exactly is the purpose of this spec?</p>
<p>
  A: This parameter determines the rendering order of the component on the page. When you actually use the dialog boxes of other mods, you might encounter this issue: I can't display the character portrait below the dialog box and options. This may be because these mods lock the rendering order. The rendered dialog box and options first, then the character portrait, at this point, will definitely be on the upper layer. And<code>renderOrder</code>This is to solve this problem. By default, the dialog box is set to 0, the options to 10, the portrait to 20, and the chat history button to 30.
</p>

<h2 id="dialogue-text" data-toc-id="dialogue-text">Dialogue text</h2>
<p>Before introducing the architecture of the dialogue file, let me first introduce my architectural design for the dialogue section, which will help you understand why this file was written this way. To summarize my dialogue structure, it looks like this:</p>
<div code="graph TD
    A[Dialogue 1] --&gt; B[Branch 1]
    A --&gt; C [Branch 2]
    B --&gt; D [Dialogue 2]
    C --&gt; D" hidecode="false" class="mermaid-render-container"
  data-type="mermaid">
  <div class="mermaid">graph TD

<p>

</p>
