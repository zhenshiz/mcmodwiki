<h1 id="接入编辑器窗口与-ai" data-toc-id="接入编辑器窗口与-ai">接入编辑器、窗口与 AI</h1>
<p>本页面向附属模组开发者。先让手动编辑、校验、保存和原生历史工作正常，再接入窗口与 AI；用户仍应能通过<a href="?file=&quot;编辑器.基础操作&quot;">通用文件流程</a>理解数据的去向。</p>
<h2 id="选择文件模型" data-toc-id="选择文件模型">选择文件模型</h2>
<table data-type="custom-table" data-with-header-row="true" style="min-width: 100px;">
<tbody>
<tr><th>类型</th><th>适合数据</th><th>接入责任</th></tr>
<tr><td>FunctionFileEditor</td><td>编辑数据就是运行时数据的功能文件。</td><td>定义 EditorFileFormat、领域目录、工程创建与加载，以及上传后的业务刷新。</td></tr>
<tr><td>ProjectFileEditor</td><td>需要保留图、布局或编译前信息的工程。</td><td>通过 IRuntimeFileProject 生成运行时数据，分别处理工程与功能文件。</td></tr>
</tbody>
</table>
<p>使用 <code>EditorAssetPaths</code> 与 <code>EditorAssetFiles</code> 统一定位、扫描和解析文件。服务端上传成功仅代表写入结果，编译、加载与业务生效由接入模组负责。</p>
<h2 id="保留同一窗口与未保存工程" data-toc-id="保留同一窗口与未保存工程">保留同一窗口与未保存工程</h2>
<p>采用 <code>ViScriptEditorWindow.open(windowID, editorCreator)</code> 并给窗口稳定的 <code>ResourceLocation</code>，可沿用最小化实例恢复与宿主切换。不要每次返回游戏时无条件创建一个新编辑器，导致当前工程被替换。</p>
<p>通过容器菜单打开时，用 <code>setGameWindowReopener(...)</code> 接回原菜单；菜单工厂继续使用上述 <code>open(...)</code> 入口，让游戏内与游戏外切换能够复用窗口实例。</p>
<p>单个视图浮动与独立缩放由 LDLib2 管理。只有确实需要游戏内指定区域缩小时，才配置 VSL 的缩小区域；它与独立桌面窗口是不同功能。</p>
<h2 id="为领域编辑器提供适配器" data-toc-id="为领域编辑器提供适配器">为领域编辑器提供适配器</h2>
<p>在 <code>ViScriptEditor#createAiEditorAdapter()</code> 返回 <code>AiEditorAdapter</code>。将模型能读、能改的范围写进说明与 Schema，使用真实领域校验，不让任意 JSON 字段直接写入项目。</p>
<table data-type="custom-table" data-with-header-row="true" style="min-width: 100px;">
<tbody>
<tr><th>方法</th><th>职责与约束</th></tr>
<tr><td>guide()</td><td>解释当前领域、字段含义和支持范围。</td></tr>
<tr><td>readSchema() / describe(...)</td><td>声明查询参数并分页返回领域数据；不泄露密钥或本机路径。</td></tr>
<tr><td>editSchema() / edit(draft, arguments)</td><td>声明修改结构，校验并只修改隔离草稿，按实际旧值和新值返回说明。</td></tr>
<tr><td>createAction(editor, draft)</td><td>创建完整可撤销的 EditAction；方法本身不修改当前项目。执行和撤销同步刷新，不递归追加历史。</td></tr>
<tr><td>setPreviewMode(editor, previewing)</td><td>预览时暂停领域修改但允许浏览，切换检查对象不应制造历史。</td></tr>
<tr><td>refresh(editor)</td><td>原生历史跳转后刷新视图，不新增历史。</td></tr>
</tbody>
</table>
<h2 id="验证用户能观察到的行为" data-toc-id="验证用户能观察到的行为">验证用户能观察到的行为</h2>
<ul>
<li><p>查询返回准确 ID、可用字段和必要的分页信息。</p></li>
<li><p>无效参数或编译失败不留下该工具调用的部分修改。</p></li>
<li><p>预览能浏览，放弃恢复完整原状态且不增加历史。</p></li>
<li><p>应用整轮只有一条历史，撤销和重做后数据与视图一致，既有手动历史仍能工作。</p></li>
<li><p>请求中手动修改、切换项目、停止和关闭窗口不会被迟到结果覆盖。</p></li>
<li><p>浮动、返回游戏、关闭与重开窗口时，同一项目状态能够正确保留。</p></li>
</ul>
<h2 id="服务器能力与权限边界" data-toc-id="服务器能力与权限边界">服务器能力与权限边界</h2>
<p>客户端编辑偏好不构成服务器授权。保存、上传和运行时修改应走可信服务端流程，并在服务端校验权限、目标、版本与数据。客户端聊天目前仅暴露领域工程工具，不把服务端 SPI 自动暴露为模型命令。</p>
<p>需要服务端只读知识查询时，使用 <code>AiKnowledgeService</code>、<code>AiQueryRequest</code> 与 <code>AiAccessContext</code>，在服务端线程读取游戏数据。提供器查询使用返回的游标继续分页，重载或环境变化后重新开始；具体 Java 接口与扩展约定见源码中的 <code>docs/ai-integration.md</code>。</p>
