<h1 id="ai-preview-apply-and-undo" data-toc-id="ai-preview-apply-and-undo">AI preview, apply and undo</h1>
<p>AI tools edit an isolated draft. With confirmation enabled, a successful turn temporarily displays that draft in the main editor so you can inspect the actual result before applying or discarding it.</p>
<h2 id="complete-one-checkable-edit" data-toc-id="complete-one-checkable-edit">Complete one checkable edit</h2>
<div currentstep="0" data-type="steps">
<div data-type="step-item"><div data-type="admonition-title">Read the current project</div><div data-type="admonition-content"><p>Ask the assistant to read the current shop and describe its categories without modifying anything.</p>
</div></div>
<div data-type="step-item"><div data-type="admonition-title">Request a concrete change</div><div data-type="admonition-content"><p>For example: “Add a Travel supplies category with 4 bread for price 2 and stock 20. Preserve the existing categories.” Enable project editing first.</p>
</div></div>
<div data-type="step-item"><div data-type="admonition-title">Inspect the real preview</div><div data-type="admonition-content"><p>After the turn finishes, inspect categories, products, counts and prices in the main editor. Browsing is available; manual editing, saving, uploading and history shortcuts are paused.</p>
</div></div>
<div data-type="step-item"><div data-type="admonition-title">Apply or discard</div><div data-type="admonition-content"><p>Use Apply turn in chat or at the top of the main editor to retain the result. Discard restores the prior project. Preview and discard add no history entry.</p>
</div></div>
<div data-type="step-item"><div data-type="admonition-title">Check whole-turn history</div><div data-type="admonition-content"><p>Undo and redo through native history. A turn adds one AI action even when it contains several tool calls.</p>
</div></div>
<div data-type="step-item"><div data-type="admonition-title">Save and publish manually</div><div data-type="admonition-content"><p>Save the local file. Export runtime data for a split-project editor and upload/reload through the owning mod when needed.</p>
</div></div>
</div>

<h2 id="what-each-stage-changes" data-toc-id="what-each-stage-changes">What each stage changes</h2>
<table data-type="custom-table" data-with-header-row="true" style="min-width: 100px;">
<tbody>
<tr><th>Stage</th><th>Main editor</th><th>Disk and server</th><th>Native history</th></tr>
<tr><td>Generating</td><td>Original project; tools modify only a draft.</td><td>No automatic save or upload.</td><td>No turn entry.</td></tr>
<tr><td>Pending preview</td><td>Temporarily shows the complete draft for browsing.</td><td>Save and upload are paused.</td><td>No preview entry.</td></tr>
<tr><td>Discard</td><td>Restores the pre-preview project.</td><td>No publication action.</td><td>No new entry.</td></tr>
<tr><td>Apply turn</td><td>Retains the turn’s result.</td><td>Still requires manual save or publication.</td><td>One entry for the whole turn.</td></tr>

<h2 id="revert-a-turn-from-chat" data-toc-id="revert-a-turn-from-chat">Revert a turn from chat</h2>
<p>The chat revert action requires that turn to remain at the current history position and the project to match its applied state. Undo later manual changes first. Native history remains the common place to inspect, undo and redo project edits.</p>
<h2 id="conflicts-and-cancellation" data-toc-id="conflicts-and-cancellation">Conflicts and cancellation</h2>
<p>The session compares a request-start snapshot before previewing so a stale draft does not overwrite manual edits made during generation. It checks again when applying or discarding. An old preview cannot be applied after switching projects. Preserve the current project and request a fresh read/edit when a conflict occurs.</p>
<p>Stopping generation drops its draft. Closing chat leaves an already-pending preview in the main editor, where Discard remains available. Starting a new chat also retracts an unconfirmed preview.</p>
<div type="info" data-type="admonition" data-admo-type="info"><div data-type="admonition-title">Disabling confirmation changes this flow</div><div data-type="admonition-content"><p>A successful turn applies automatically when confirmation is off. It still produces an undoable native action, but does not stop at a pending confirmation preview.</p>
</div></div>
