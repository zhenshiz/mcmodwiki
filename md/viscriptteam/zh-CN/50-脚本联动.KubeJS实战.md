<h1 id="kubejs-脚本实战" data-toc-id="kubejs-脚本实战">KubeJS 脚本实战</h1>
<p><a href="?file=&quot;学习路线&quot;">学习路线与视频目录</a> · <a href="?file=&quot;排错与数据维护&quot;">排错与数据维护</a></p>
<p>安装 KubeJS 后，可在服务端脚本中调用 VST 工具类操作阵营、队伍与声望。这里显式加载 ViScriptTeamServerUtil；客户端工具类仅提供名牌态度缓存等客户端功能。</p>
<div type="info" data-type="admonition" data-admo-type="info"><div data-type="admonition-title">区分服务端与客户端工具类</div><div data-type="admonition-content"><p>如果同名 ViScriptTeamUtil 绑定被解析为 ViScriptTeamClientUtil，调用 createFaction 等方法会失败。下面用 Java.loadClass 明确选择服务端类，避免同名绑定混淆；不要在客户端脚本中执行这些修改。</p>
</div></div>
<h2 id="一次性建立地图阵营" data-toc-id="一次性建立地图阵营">一次性建立地图阵营</h2>
<pre language="javascript" isclosed="false"><code class="language-javascript">// kubejs/server_scripts/vst_factions.js
ServerEvents.loaded(event =&gt; {
  const server = event.server
  const state = server.persistentData
  if (state.getBoolean(&#x27;vst_tutorial_factions_v1&#x27;)) return

  const level = server.overworld()
  const vst = Java.loadClass(&#x27;com.viscript_team.util.ViScriptTeamServerUtil&#x27;)
  vst.createFaction(level, &#x27;tutorial_guards&#x27;)
  vst.createFaction(level, &#x27;tutorial_raiders&#x27;)
  vst.addEnemyFaction(level, &#x27;tutorial_guards&#x27;, &#x27;tutorial_raiders&#x27;)
  vst.addEnemyFaction(level, &#x27;tutorial_raiders&#x27;, &#x27;tutorial_guards&#x27;)

  state.putBoolean(&#x27;vst_tutorial_factions_v1&#x27;, true)
})</code></pre>
<p>第一次启动会创建并设置双向关系，随后用世界持久化标记跳过。修改脚本不会重新执行已完成的初始化；要迁移旧数据时写新的明确迁移逻辑。不要在每次登录事件中无条件 setPlayerStanding，否则会重置玩家已经获得的声望。</p>
<h2 id="读取个人与队伍声望" data-toc-id="读取个人与队伍声望">读取个人与队伍声望</h2>
<pre language="javascript" isclosed="false"><code class="language-javascript">// Call from your own server-side quest or dialogue callback.
function inspectGuardStanding(player) {
  const vst = Java.loadClass(&#x27;com.viscript_team.util.ViScriptTeamServerUtil&#x27;)
  const personal = vst.getPlayerStanding(player, &#x27;tutorial_guards&#x27;)
  const effective = vst.getPlayerEffectiveStanding(player, &#x27;tutorial_guards&#x27;)
  const partyId = vst.getPlayerPartyId(player)
  player.tell(&#x27;Personal: &#x27; + personal + &#x27; | Effective: &#x27; + effective)
  if (partyId == null) return

  const leaderValue = vst.getPartyEffectiveStanding(
    player.serverLevel(), partyId, &#x27;tutorial_guards&#x27;, &#x27;leader&#x27;
  )
  player.tell(&#x27;Party: &#x27; + partyId + &#x27; | Leader strategy: &#x27; + leaderValue)
}</code></pre>
<p>上例只是函数定义，不会自动执行；在自己的服务端任务或对话回调中传入 ServerPlayer 调用。无队伍时 getPlayerPartyId 返回 null；不要把界面显示名当固定 ID。</p>
<h2 id="在任务结算时改变声望" data-toc-id="在任务结算时改变声望">在任务结算时改变声望</h2>
<pre language="javascript" isclosed="false"><code class="language-javascript">// Run once from a verified server-side settlement callback.
const vst = Java.loadClass(&#x27;com.viscript_team.util.ViScriptTeamServerUtil&#x27;)
vst.addPlayerStanding(player, &#x27;tutorial_guards&#x27;, 25)
// A fixed setting replaces the value rather than adding to it:
// vst.setPlayerStanding(player, &#x27;tutorial_guards&#x27;, 100)</code></pre>
<p>player 由结算回调提供，不是全局变量；不要单独把这段放在脚本顶层。用任务状态或自己的持久化标记确保奖励不重复发放。先查询个人声望变化，再查询队伍 min；一个人的提升不保证全队有效声望提高。</p>
<h2 id="常用接口及边界" data-toc-id="常用接口及边界">常用接口及边界</h2>
<table data-type="custom-table" data-with-header-row="true"><tbody><tr><th>接口</th><th>输入和结果</th><th>用途</th></tr><tr><td>createFaction(level, id)</td><td>ServerLevel，已存在返回 false。</td><td>初始化势力。</td></tr><tr><td>setEntityFaction(entity, id)</td><td>服务端实体；按该实体 UUID 设置。</td><td>在刷怪或 NPC 创建后分配归属。</td></tr><tr><td>getPlayerEffectiveStanding(player, id)</td><td>默认 min；另有 strategy 字符串重载。</td><td>制作与内置规则一致的门槛。</td></tr><tr><td>getPartyEffectiveStanding(level, partyId, id, strategy)</td><td>min / average / leader / max；队伍不存在可返回 null。</td><td>明确选择剧情评价方式。</td></tr><tr><td>joinParty(player, partyId)</td><td>会先退出原队；返回是否发生变化。</td><td>仅用于作者明确设计的强制调队。</td></tr><tr><td>canHurt(attacker, target) / canTarget(attacker, target)</td><td>LivingEntity；返回 VST 关系许可。</td><td>供自定义战斗逻辑查询；不保证有攻击动作或能造成伤害。</td></tr></tbody></table>
<h2 id="与-vsq-等系统配合" data-toc-id="与-vsq-等系统配合">与 VSQ 等系统配合</h2>
<p>VST 提供队伍身份与关系数据；任务是否同步、奖励如何分配由对应任务模组的联动逻辑决定。VSQ 的队伍进度与队长奖励请同时核对 VSQ 文档。不要把 VST 队伍当作原版 scoreboard team，也不要假定所有任务模组都自动接入。</p>
